  commandLine("python3", ...) in build.gradle.kts:44. The python.org installers
  put python.exe and py.exe on PATH, not python3.exe, so unless the Store build
  is installed the task can't start the process. README says so and gives -x 
  contextBudget. Left the build file alone — a fallback chain there is code for
  a machine nobody has yet.

  POSIX audit — nothing else breaks, and I checked by running rather than
  reading:

  - Paths are java.nio.file throughout; no separators are spelled out anywhere
  in src/.
  - The case-ID-as-filename was already Windows-safe on purpose (epoch millis,
  not an ISO instant with colons).
  - Atomic.write uses ATOMIC_MOVE, REPLACE_EXISTING, which Windows supports on a
  same-volume move; Files.write emits the platform separator and readAllLines
  strips it, so the cache and case files are self-consistent either way.
  - The real risk was fixture contents, not paths: a CRLF checkout puts a stray
  \r in every row's last cell. I converted fixtures/*.csv to CRLF and ran the
  CLI and the full demo — conversion, sanctions, judicial, the 2s timeout, the
  review round trip and the cache hit (400ms → 195ms) all behaved, because every
  last-cell read is trimmed. Fixtures restored with git checkout. That run
  added one row to the gitignored data/bureau-cache.csv.
