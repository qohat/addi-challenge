     Repo bootstrap — Addi lead validation challenge

     Context

     The repo is a seed: docs/brief.md, docs/BRAIN.md, docs/RULES.md,
     prompts/start.txt, two Python scripts, a .gitignore. No build, no source,
     no
     specs.

     BRAIN.md is the author's working method and carries across projects.
     RULES.md is this project's settled decisions. The bill for this project is
     dominated by re-read context (96.5% cache reads on the last run), so the
     bootstrap's job is to put every fact in exactly one place, sized by how
     often
     that place is loaded: 40 lines for the always-resident router, 120 for
     load-once-per-session files, 150 for a spec.

     Outcome: a repo an agent can orient itself in for four cheap reads, with
     the
     spec queue, operating rules, style guide and decision records in place —
     and
     nothing from the build, which is spec 00 and must appear in git history as
     built rather than seeded.

     Constraints

     - No Gradle files, no Dockerfile, no CI workflow, no src/. Spec 00 builds
     those.
     - No MCP servers, no .mcp.json, ever.
     - No spec files, no code.
     - Everything in English. No emojis anywhere.
     - docs/BRAIN.md untouched. docs/RULES.md deleted at the end — its content
     moves into the files below and the seed commit keeps it in history.
     - .gitignore extended, never replaced.

     Settled this session

     Four gaps the brief left and RULES.md did not close. These go into
     docs/PROJECT_CONTEXT.md and docs/assumptions.md as decided, not open.

     1. validate-lead takes the national ID and nothing else. The lead already
     exists in the CRM, which is the local DB, so the ID selects the record and
     every other field is read from it. No dead flags. Email format validation
     therefore belongs to fixture parsing at seed time, not to CLI parsing.
     2. Manual review gets one command: review resolve <case> 
     --approve|--reject.
     No list, no show — the queue directory is browsable with ls and cat,
     and the CLI stays as simple as the brief asks for.
     3. Latency is carried per row in the external-system fixtures, alongside
     the
     outcome, so one demo ID can make the registry take 5s and fire the real 2s
     scope timeout. The port still performs the delay; the fixture supplies the
     duration.
     4. The CLI lands before the real adapters. Early specs return dummy
     outcomes
     through the real types and the adapters get wired in incrementally, so a
     reviewer can run the real command from spec 02 onward.

     CONTRIBUTING.md — layer 1, budget 120 lines

     Every rule stated with its reason in one clause, because a rule with a
     reason
     gets applied correctly in unanticipated cases and a bare prohibition gets
     applied literally and wrongly.

     - Sealed interfaces plus records for anything with cases; exhaustive switch
     with no default on a closed type — a catch-all defeats the only compiler
     check the design leans on.
     - No generic Result<T, E>; each step returns its own type named after its
     domain, with cases named after what happened.
     - Errors are values. Exceptions only for the genuinely unrecoverable,
     caught at
     the boundary and translated into domain values immediately; custom
     exceptions
     carry no stacktrace (super(msg, null, false, false)) because filling one in
     is expensive and nobody reads it.
     - Domain purity: no I/O, clock, randomness or logging in the domain; every
     effect enters through a port and executes at the boundary.
     - Domain failure and outside-world failure are different branches,
     collapsed
     into one decision in exactly one exhaustively matched place.
     - Immutable by default: records, List.copyOf, no setters, no mutable
     collection escaping its boundary.
     - Total functions, no nulls in the domain. Parse, don't validate — input
     crosses
     the boundary once and becomes a valid type.
     - Illegal states unrepresentable: a validated thing and an unvalidated
     thing are
     different types, which is cheaper than any test.
     - Concurrency only in the orchestration layer. Java 25 shape:
     StructuredTaskScope.open() with scope.fork(...) and scope.join() — the
     Java 21 new StructuredTaskScope<>() / ShutdownOnFailure API does not
     compile here and writing it is a training-data artefact.
     - Plain language features over libraries.
     - Tests: JUnit 5, written from the spec and watched to fail first.
     Hand-written
     fakes implementing the ports, no mocking framework. Determinism by
     construction — clock, randomness and latency are ports with fixed seeds.
     - If a paragraph of comment is defending an awkward construct, fix the
     design.
     - No emojis in code, commits, PRs or output.
